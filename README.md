# パーソナルニュースアプリ α版

公的機関・企業などの一次情報を扱う個人用ニュースアプリのα版です。公式サイトの RSS/Atom からニュースを集め、カテゴリ別に一覧表示し、記事を開くと発信元ページから抽出した概要を表示します。

## 主要機能
- **マイニュース**（最初のタブ）: 関心プロフィールに一致する記事を、関連度と新しさで並べて表示。各記事に「なぜ表示されたか」（一致した関心トピック）を表示
- 関心プロフィールは画面右上の設定ボタンから編集（トピックの追加・削除、キーワード、優先度、オン／オフ）
- カテゴリタブ（すべて / 政治 / 経済 / 投資 / 社会 / 国際 / テクノロジー / 生成AI / サイエンス）。カテゴリごとに色分け
- 各タブで地域（日本 / カナダ / 米国 / 欧州 / グローバル）と発信元（公的機関 / 企業 / 研究機関 / 報道機関）を選択。選択はタブごとに保持
- 記事をタップすると詳細画面へ。要約と要点、本文の冒頭、「元記事を読む」ボタンを表示
- キーワード・ハッシュタグ検索、記事の共有、ダークモード

## 実行方法
```bash
npm install
npm run dev
```

設定を変える場合は `cp .env.example .env` を実行して `.env` を編集します（設定しなくても全機能が動作します）。

## 要約
要約エンジンは差し替え可能で、`.env` の `SUMMARY_PROVIDER` で選びます。

| エンジン | 内容 | 費用・依存 |
|---|---|---|
| `extractive`（既定） | 生成AIを使わず、本文を文に分けて採点し（見出しとの関連・文書内での中心性 [TextRank]・冒頭からの位置）、重要な文をそのまま抜き出す。数値や日付を含む文を「要点」にする | 費用ゼロ、外部サービス不要、オフラインで動作。本文にないことは書かない |
| `local` | 手元やオンプレミスで動かすオープンソースのモデル（Qwen、Gemma、Llama、日本語特化モデルなど）が要約を書く。Ollama / LM Studio / llama.cpp / vLLM の OpenAI 互換 API に対応 | 自前の計算資源のみ。英語記事の日本語訳もできる |
| `claude` | Claude API（`claude-opus-5-5`）が要約を書く | API 利用料。`ant auth login` または API キーが必要 |

- 要約の根拠は発信元の本文のみ（PDF 資料はテキストを取り出して使う）。会社概要・問い合わせ先・定型文は除外します。
- LLM の呼び出しに失敗した場合は、自動で抽出型の要約に切り替えます。
- LLM の誤り対策: 本文がほとんど取れない記事（リンク集のページ等）は LLM に渡さず、取得に失敗した記事は後で再試行します。LLM の出力に本文にない数値が含まれる場合、その要点は除外し、要約本文に含まれる場合は採用しません。ただし、数値の取り違え（1株利益を純利益と書く等）や本文にない解釈までは検出できません。
- `local` の検証結果（2026年10月、M2 / メモリ 8GB の Mac、`qwen3:4b`）: 抽出型より記事の核心をよく捉え、英語記事も日本語で要約できる一方、1件 30〜75 秒かかり、小さな誤り（指標の取り違え、本文にない補足、誤字）が見られました。実用には、より大きなモデルを GPU サーバー等で動かすことを推奨します。
- 作成した要約は `data/summaries.json` に保存し、エンジンを切り替えた場合は新しいエンジンで作り直します。
- 抽出型は軽いため、新着記事（最新80件）を自動で事前に要約し、一覧のカードにも表示します。LLM の場合は `AUTO_SUMMARY_LIMIT` の件数まで。
- 画面上では、抽出型は「要約（本文から抜粋）」、LLM は「AI要約（モデル名）」と区別して表示します。

## 情報源とカテゴリ
| カテゴリ | 日本 | カナダ | 米国・欧州・グローバル |
|---|---|---|---|
| 政治 | 首相官邸、総務省 | カナダ政府（全省庁）、オンタリオ州政府 | 米国務省 |
| 経済（公的機関） | 日本銀行、財務省、経済産業省、金融庁、JPX | カナダ銀行、カナダ統計局、カナダ政府（財務・地域経済開発など） | FRB、ECB |
| 経済（企業・報道） | PR TIMES、@Press（企業活動に関する発表のみ） | CBC Business | PR Newswire（決算・M&A・一般ビジネス） |
| 投資 | GPIF、PR TIMES（資金調達など） | | PR Newswire（Venture Capital） |
| 社会 | 厚生労働省、文部科学省 | CBC キッチナー・ウォータールー、カナダ政府（保健・移民など） | 米CDC |
| 国際 | JETRO ビジネス短信 | カナダ政府（グローバル・アフェアーズ） | WHO、欧州委員会、英国外務省 |
| テクノロジー | デジタル庁、JST | カナダ政府（ISED）、CIFAR、Vector Institute、CBC Technology | NIST、NSF、NVIDIA、欧州委員会（デジタル政策）、IEEE Spectrum（ロボティクス）、arXiv（Physical AI 関連論文） |
| 生成AI | Sakana AI、PR TIMES（生成AI関連のみ） | | OpenAI、Google DeepMind、Google |
| サイエンス | | | Simons Foundation、Quanta Magazine |

報道機関（CBC、IEEE Spectrum、Quanta Magazine）は、一次情報の配信がない地域ニュースや、研究成果の解説に限って使い、「報道」と表示します。

上記に加え、見出し・説明文に含まれる語で次のように分類します（`src/newsPipeline.ts` の `CATEGORY_RULES`）。
- 企業の発表のうち、提携・買収・決算・業績修正・上場・工場や生産・値上げ・事業終了・経営体制の変更・倒産、および事故や不祥事（リコール、不正アクセスや情報漏えいの報告、システム障害など）に関するものは **経済** に入れる（英語の発表も同様: acquisition, earnings, IPO, recall, data breach など）
- 「資金調達」「シリーズA」「国内投資」などを含む記事は **投資** に入れ、経済からは外す
- 「生成AI」「LLM」「AIエージェント」などを含む記事は **生成AI** にも表示する
- 日本の情報源で「首脳」「外相」「国連」などを含む記事は **国際・日本** にも表示する

公的機関の発表が経済カテゴリの大半を占めないよう、次のように制限しています。
- 日本銀行・財務省・金融庁は1日6件、経済産業省は8件まで（FRB・ECB は6件まで）
- 入札・落札結果、国庫短期証券の発行、職員募集、説明会などの定型的なお知らせは除外
- 企業発表のうち、法律事務所による集団訴訟の勧誘、ウェビナー・セミナー告知、翻訳版（英語以外の PR Newswire 配信）は除外

## マイニュース（パーソナライズ）
- 関心トピックごとに日本語・英語のキーワードを持ち、記事の見出し・説明文・要約に含まれるかで一致を判定します（生成AIは使いません）。見出しで一致した記事は、本文で触れているだけの記事より高く評価します。
- トピックには条件を付けられます: 地域の限定（例: 米国・EU のテック政策）、発信元の種類の限定（企業ブログを除く等）、両方の語を含む場合のみ（例: 日本×カナダ）、特定の発信元は常に対象（例: CBC キッチナー・ウォータールー）、単独では表示せず他の関心と重なる記事を上位にする（例: 提携・資金調達）。
- 並び順は「一致したトピックの優先度の合計 × 新しさ（3日で半分）」です。
- プロフィールは `data/profiles/<ID>.json` に保存します（現在は1人分。複数ユーザー化の際はユーザーごとの ID で切り替える想定）。初期設定は `src/profile.ts` の `DEFAULT_PROFILE` です。

## 設計方針
- 一覧の説明文（100文字以内）は RSS の説明文をそのまま短縮したもの。要約は発信元の本文のみを根拠に作成し、抜粋か AI による要約かを明示する
- 要約は特定の AI サービスに依存しない。既定は生成AIを使わない抽出型で、必要に応じてオープンソースのモデルや API に差し替えられる
- ハッシュタグは発信元・カテゴリ・地域の事実のみから生成する
- 全文は表示せず、必ず「元記事を読む」から発信元で確認できるようにする

## 運用メモ
- フィードを追加・変更する場合は `src/newsPipeline.ts` の `officialFeeds` 配列を更新してください。
- フィードは10分間サーバー側でキャッシュします。取得はフィードごとに8秒でタイムアウトします。
- フィードに画像がない記事は、新しいものから順に記事ページの画像（og:image）を裏で確認し、サムネイルに使います（1記事1回のみ。サイト共通のロゴ画像は除外）。
- 取得した記事は `data/news-archive.json` に30日分蓄積します（PR TIMES のように新着の入れ替わりが速いフィードでも、一定期間分を表示するため）。削除すると次回取得分から作り直します。
- PR TIMES・@Press は最新分（数時間分）しか配信しないため、企業の発表はサーバーを起動している間に蓄積されます。停止中に配信された発表は取り込めません。
- 東証の適時開示（TDnet）は robots.txt で自動取得が禁止されているため、取得していません。
- 全フィードの取得に失敗し、蓄積データもない場合のみ「サンプル」バッジ付きの記事を表示します（実在の発表ではありません）。
- 取得に失敗したフィードはサーバーのログに `[feed] 発信元名: 理由` の形式で表示されます。

## API
- `GET /api/categories` — カテゴリと地域の一覧
- `GET /api/news?category=&subgroup=&sourceType=&keyword=&offset=&limit=`（`subgroup` は地域） — 記事一覧（総件数は `X-Total-Count` ヘッダー）
- `GET /api/news/:id` — 記事、発信元ページから抽出した本文の冒頭、保存済みの要約
- `GET /api/news/:id/summary` — 要約（未作成なら作成して保存）
- `GET /api/config` — 使用中の要約エンジン
- `GET /api/news?forYou=1` — マイニュース（関連度順。各記事に一致した関心トピック `matches` を付与）
- `GET /api/filters` — カテゴリ・地域・発信元の種類の一覧
- `GET /api/profile`・`PUT /api/profile`・`POST /api/profile/reset` — 関心プロフィールの取得・保存・初期化
